# Code of Conduct — ZENO

## Our Commitment

ZENO is a team project built by four undergraduate students collaborating under sprint deadlines. This Code of Conduct sets expectations for how we work together so the project stays productive, fair, and respectful for everyone involved, including any external contributors or reviewers.

## Expected Behavior

- Communicate clearly and respectfully in commits, pull requests, issues, and team discussions.
- Give constructive, specific feedback during code reviews — critique the code, not the person.
- Respect each member's owned feature area (see README) while remaining open to input across the codebase.
- Meet sprint commitments, and communicate early if a deadline is at risk rather than going silent.
- Credit teammates' work accurately; don't claim sole authorship of shared or reviewed contributions.
- Keep disagreements about technical decisions focused on evidence and trade-offs, not personal preference framed as fact.
- Protect sensitive data (API keys, `.env` files, payment sandbox credentials) — never commit secrets to the repository.

## Unacceptable Behavior

- Personal attacks, insults, or dismissive comments toward any team member or contributor.
- Discrimination or harassment based on gender, ethnicity, religion, disability, or any other personal characteristic.
- Deliberately submitting broken or untested code to a shared branch without disclosure.
- Taking credit for another member's work in reports, presentations, or commit history.
- Ignoring agreed sprint scope to unilaterally rewrite another member's module without discussion.
- Public shaming of a teammate's mistakes instead of addressing them privately or in a constructive review.

## Scope

This Code of Conduct applies to all project spaces: the GitHub repository (issues, pull requests, commits, discussions), team meetings, shared documents, and any other channel used to coordinate ZENO development.

## Reporting and Resolution

If a conflict or violation arises:

1. Raise the concern directly with the team member involved, where appropriate.
2. If unresolved, bring it to the full team for discussion during a scheduled sync.
3. If the issue involves academic integrity or cannot be resolved internally, escalate to the course instructor or supervising faculty.

## Enforcement

Repeated or serious violations may result in:
- A documented warning within the team.
- Reassignment of feature ownership for the affected module.
- Escalation to the course instructor for academic review.

## Attribution

This Code of Conduct was written for the ZENO project team and adapted for the context of a university software engineering course project.
